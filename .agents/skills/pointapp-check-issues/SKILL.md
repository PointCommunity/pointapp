# PointApp Check Issues

Read `AGENTS.md`, verify `PointCommunity/pointapp`, and record timestamp,
branch, `HEAD`, tree, worktree, GitHub access, and Project visibility.
Perform read-only operations.

Inventory every open Issue and dedicated PointApp Project card. Read full Issue
bodies and the PR/branch/check/comment evidence needed to reconstruct Status,
Priority, Impact, Effort, labels, assignee, target-platform baton, candidate,
approvals, findings, integration state, and next gate. Count all active lanes.

Lead with the active Issue and one next action. Report:

1. global active slot and drift;
2. each active Issue with linked PR/head evidence;
3. direct-attention inconsistencies;
4. classification of every open Issue;
5. operational priority plus a separate ready-Backlog queue;
6. evidence time and repository identity;
7. `No changes were made.`

Mark unknown and stale evidence honestly. Do not mutate Project, Issue, PR,
branch, or local files.
