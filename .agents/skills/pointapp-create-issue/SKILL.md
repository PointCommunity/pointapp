# PointApp Create Issue

Read `AGENTS.md`, verify repository and Project identity, preserve local work,
then inspect every open Issue and relevant code/spec/PR evidence for overlap.
Use [Issue design](references/issue-design.md) to resolve product intent.

Create exactly one Issue only after the human approves the complete title,
body, labels, Priority, Impact, and Effort with the explicit signal
`Approved to create this exact GitHub Issue` or an unambiguous equivalent.
Approval applies only to the displayed draft.

The created Issue is open, unassigned, linked to the dedicated PointApp
Project, fully classified, and in `Backlog`. It has no branch, PR, active-slot
claim, native target baton, or approval. Read all fields back immediately.
Issue creation may occur while another Issue is active because it does not
start work. Route implementation through `pointapp-work-issue`.
