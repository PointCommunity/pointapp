# PointApp Issue analysis

Keep this analysis read-only. Account for every open Issue and classify it as
active gate, ready Backlog, blocked/dependent Backlog, needs clarification,
`On Hold`, duplicate/superseded, or pipeline drift.

Inspect the full Issue, Project Status/Priority/Impact/Effort, labels,
dependencies, overlap, repository evidence, and linked PRs. Rank ready work by
user safety, Builder-contract foundation, native build reliability, user
impact, dependency value, urgency, readiness, risk, cross-platform burden, and
effort. Show recorded Project metadata separately from inferred judgment.

Operational priority comes first: repair active-slot drift or continue the
active Issue. With a free slot, recommend an ordinal Backlog queue and name each
blocked item's return condition. Lead a recommendation with `Work Issue #X`
and wait for the human's choice.
