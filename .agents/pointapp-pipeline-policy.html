PointApp development and release pipeline

PointCommunity/pointapp is the production source for the Android and Apple app shell. PointApp Builder is a separate product that publishes versioned data to the installed shell. This policy adopts Spectrune's Issue-first pipeline while aligning the native gates to two target platforms that can be tested locally from one Mac.

Two release planes

Native binary

Compiled components, permissions, native modules, identifiers, signing, and runtime behavior.

Development→Android + Apple beta→Store production

App configuration

Content, navigation, layout, theme tokens, media references, and settings supported by compiled capabilities.

Draft→Staging→Exact production release

Hard boundary: Builder output is data. It never injects executable code, adds a native permission, names an arbitrary component, or exposes a privileged bridge.

One active Issue

Backlog→In progress→Pending Review→In review→Done

In progress, Pending Review, and In review share one repository-wide slot. On Hold releases it. The Issue is the work unit, its Project card is the lane, its sole assignee is the action owner, and its durable status record names the current Android or Apple validation target.

Native target loop

  1. Implement both target paths on one feature branch using a reviewed HTML specification and test-first slices.
  2. Commit the complete candidate locally. Record commit, tree, app/runtime versions, configuration fixture release/digest, target device, and artifact checksum.
  3. Build, install, and launch the first target's local beta. Automated success means ready for user testing.
  4. Present the complete checklist and wait for explicit Beta approved - Android or Beta approved - Apple.
  5. After first-target approval, push the exact branch and open the canonical linked PR. Validate the other target against that pushed head.
  6. Any runtime remediation creates a new candidate and repeats affected target approvals. Merge only when the exact latest head holds both target approvals and every required check.

Builder publication

RoleMaximum publication authority
EditorEdit and preview drafts.
PublisherPublish an exact candidate to Staging.
AdministratorPromote the exact verified Staging release to Production.
Installed appRead the configured channel, validate immutable releases, cache atomically, and fall back safely. It never writes production.

Candidate identity

A reviewable native candidate is the tuple of Issue, PR/branch, commit, Git tree, app version, runtime version, target, installed artifact checksum, configuration fixture release ID and digest, automated gates, and the target-specific human result. A production configuration candidate is an immutable Staging release ID and digest promoted without rebuilding it.
