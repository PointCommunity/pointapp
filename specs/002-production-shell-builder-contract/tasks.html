PointApp production shell tasks

Tasks are dependency-ordered and intentionally small. App implementation remains unchecked pending specification and framework approval.

Foundation

☑ Task 0 · Adopt repository governance

Install the PointApp-tailored policy, skills, adapters, pipeline, research, specification, plan, ADRs, foundation checks, and CI workflow locally.

Acceptance: nine PointApp workflow skills and five shared design skills align; every human artifact is dark HTML; no app/Builder/store mutation occurs. Verify: npm run check and the skill audit.

☑ Task 1 · Resolve mobile identity and support matrix

Accepted Expo SDK 57 and TypeScript; recorded organization-owned IDs, supported OS floors, representative handset/tablet targets, physical-device evidence requirements, and the shared adaptive viewport model.

Dependencies: Task 0. Acceptance: D1–D3 have explicit answers in accepted HTML ADR/spec updates. Verify: review record and foundation checks. Files: ADRs 0002–0003, spec, environment matrix.

☑ Task 2 · Enable local iOS and Android toolchains

Installed and verified the iOS 26.5 Simulator runtime, current iPhone and 11-inch iPad simulators, Android Studio and CLI, JDK 17, Watchman, API 35/36 SDK packages, and named API 36 phone/tablet AVDs.

Dependencies: Task 1. Acceptance: all four viewport targets completed boot and the redacted native preflight passes. Verify: npm run check:native-env and the native environment report. Files: preflight script/test and environment report.

☑ Task 3 · Establish the governed GitHub Project

Created and linked the private PointApp organization Project with the exact controlled Status, Priority, Impact, and Effort fields and the one-active-Issue workflow policy.

Dependencies: Task 0. Acceptance: Project #3 readback proved the controlled schema and zero active Issues before Issue #1 entered In progress. Verify: live Project and Issue readback. Operational state: live GitHub state remains authoritative.

Native shell

☐ Task 4 · Scaffold the accepted app foundation

Create the minimal current Expo/React Native TypeScript shell with development builds, stable scripts, one bundled bootstrap route, and no remote fetch.

Dependencies: Tasks 1–2. Acceptance: one source tree launches on both local targets. Verify: types, lint, tests, iOS and Android launch. Likely files: package/app config, route entry, bootstrap fixture, focused test.

☐ Task 5 · Isolate development, beta, and production channels

Define distinct IDs, storage namespaces, endpoints, visible labels/icons, runtime versions, and no-submit build profiles.

Dependencies: Task 4. Acceptance: one channel cannot read/write another channel's state. Verify: generated-config tests and installed target inspection. Likely files: app config, channel module, build profiles, tests.

Contract and recovery

☐ Task 6 · Define release envelope and fixtures

Create contract v1 schemas, types, canonicalization rules, stable component/capability IDs, and valid/hostile fixtures.

Dependencies: Task 4. Acceptance: deterministic schema/digest and rejection behavior are testable without UI. Verify: focused and full contract tests. Likely files: schema, types, canonicalizer, fixtures, tests.

☐ Task 7 · Implement validation and safe selection

Validate organization, schema, compatibility, capabilities, integrity/authenticity interface, URLs, and references before selecting a release.

Dependencies: Task 6. Acceptance: every hostile fixture fails closed with a safe typed reason. Verify: red-green contract suite. Likely files: validator, selector, URL policy, tests.

☐ Task 8 · Implement atomic cache and fallback

Add bundled bootstrap, channel-pointer fetch, immutable release fetch, atomic storage, last-known-good, offline/corrupt/interrupted recovery, and safe diagnostics.

Dependencies: Tasks 5 and 7. Acceptance: no failed candidate replaces a usable release. Verify: integration fault matrix on both targets. Likely files: client, cache, fallback, diagnostics, tests.

First vertical experience

☐ Task 9 · Implement adaptive viewport primitives

Add a pure current-window classifier, responsive context/hook, safe-area and text-scale inputs, and state-preserving class changes without device-model checks.

Dependencies: Task 4. Acceptance: compact below 600, medium at 600–839, and expanded at 840+ are deterministic and update live. Verify: focused unit and integration tests at boundary widths, rotation, and resizing. Likely files: viewport types, classifier, hook/context, tests.

☐ Task 10 · Render configurable navigation and one page

Implement only the approved registry elements and render the same fixture at compact, medium, and expanded widths on Android phone/tablet and iPhone/iPad.

Dependencies: Tasks 7–9. Acceptance: agreed navigation/page flow, state preservation, loading/error/offline states, platform-native accessibility, and no arbitrary components or styles. Verify: unit, integration, native flow, accessibility, resizing, and visual parity. Likely files: registry, navigation shell, page renderer, components, tests.

☐ Task 11 · Complete exact-candidate dual-platform beta

Build, install, launch, and validate one committed candidate on Android and Apple across handset and tablet viewports using the same fixture digest and separate platform approvals.

Dependencies: Task 10. Acceptance: both approvals and all checks name the exact latest tree and include compact/medium/expanded evidence. Verify: PointApp gates and durable Issue/PR record. Likely files: build evidence, test report, changelog if findings change behavior.

Builder hand-off and release

☐ Task 12 · Publish contract v1 for Builder consumption

Package or expose the exact reviewed schemas, semantic layout variants, generated types, fixtures, and conformance commands without coupling repositories at runtime.

Dependencies: Task 11. Acceptance: an independent consumer reproduces all fixture and layout-variant outcomes. Verify: clean-room conformance run. Likely files: contract package metadata, generated artifact, conformance script/test.

☐ Task 13 · Integrate Builder Staging and Production

In the future Builder repository, implement role-gated exact-candidate publication and rollback; then point PointApp beta/production at their respective channels.

Dependencies: Task 12 and separate Builder approval. Acceptance: Builder-authored release updates both native clients and all viewport classes without binary change. Verify: preview/Staging/native viewport parity and rollback. Repository: Builder work occurs outside this repository.

☐ Task 14 · Prepare signed store candidates

Complete real-device handset/tablet and store-track evidence, privacy/permission declarations, signing, staged rollout, monitoring, and rollback rehearsal.

Dependencies: Tasks 11 and 13. Acceptance: exact authorized Android and Apple store candidates are review-ready across required form factors. Verify: native/store checklists and artifact identity. Submission remains a separate explicit authorization.
