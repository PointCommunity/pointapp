ADR 0001: Separate the production app shell from PointApp Builder

Accepted · September 7, 2026

Context

PointApp needs a store-delivered Android and Apple framework whose content, navigation, layouts, and supported elements can change through a separate Builder. Store policy, offline reliability, rollback, and security require a strict distinction between compiled behavior and remote data.

Decision

PointCommunity/pointapp owns the production native shell and configuration consumer. A separate PointApp Builder owns authoring. Builder publishes immutable data releases composed only from component and capability IDs compiled into the shell. The app validates schema, organization, capability, integrity, URL safety, and compatibility before atomically activating a release. It always retains a bundled bootstrap and last-known-good release.

Release separation

  • Native code travels through local Android and Apple beta approval and store release.
  • Configuration travels through draft, Staging, exact-candidate Production publication, and rollback.
  • Neither release plane grants authority over the other.

Alternatives considered

  • Bundle all content into each store release: rejected because ordinary content changes would be slow and rollback would require a binary release.
  • Download executable UI or arbitrary scripts: rejected because it weakens trust boundaries and conflicts with store restrictions on downloaded code that changes functionality.
  • Place Builder and app source in one repository: rejected because authoring deployment, content publication, native signing, and store release require different ownership and gates.

Consequences

  • The configuration schema and compiled registry become public interfaces that require versioning and compatibility tests.
  • Builder preview and both native clients need shared deterministic fixtures and parity evidence.
  • A new native capability requires a binary release before Builder may publish configuration that depends on it.
  • Rollback can move a production pointer to an earlier immutable configuration without a store release.
